# Deviations from upstream Omarchy

Everything not listed here is upstream's own code and configuration, unchanged.

| Area | Upstream (Arch) | Here (Ubuntu 24.04) | Why |
|---|---|---|---|
| Display manager | SDDM with Omarchy's Qt6 theme | GDM, `omarchy.desktop` wayland session (uwsm); packaged `Hyprland` entry as fallback | Omarchy's theme needs SDDM 0.21; noble ships 0.20 |
| Boot splash | Plymouth theme through `plymouth-set-default-theme` and mkinitcpio | same theme in `/usr/share/plymouth/themes/omarchy` via `update-alternatives` and `update-initramfs` (step 59, the Plymouth patch: stable `0007`, rc `0006`); Style > Unlock recolours it per theme | no mkinitcpio on Ubuntu |
| Packages | pacman, AUR, `omarchy-pkg-*` | each `omarchy-pkg-*` helper hands over to `omarchy-pkg-ubuntu` in one line at the top when there is no pacman, so upstream's pacman lines stay untouched (fork patch 0001); apt, official .debs from GitHub releases, mise for what its registry carries (herdr, cliamp, the agent CLIs), source builds for the rest; `omarchy-pkg-installed` maps Arch names to dpkg/snap/flatpak/command | no pacman; mise first is the user's rule |
| Install menu | pacman, AUR and Omarchy's repository (`pkgs.omarchy.org`) by Arch name | `omarchy-pkg-ubuntu` (fork patch 0001) resolves each Arch name to an apt alias or a recipe: the vendor's apt pool or repository, a vendor .deb, the Omarchy package extracted with a manifest in `/var/lib/omarchy-ubuntu/opr`, a flatpak, mise, a Nerd Fonts archive, i386 multiarch, libretro buildbot cores and assets at Arch's paths, Zed's installer, Zen's tarball in `/opt/zen-browser`; the AUR entry opens the apt picker with a note | no AUR on Ubuntu, and installers read the paths and scripts Omarchy's packages carry. apt updates what came from a repository or from a .deb that registers its source (Brave, Signal, Sublime Text, NordVPN, Grok Bot, ChatGPT, Edge, Chrome, VS Code, Cursor, Slack, Spotify); Omarchy packages (Claude, supergfxctl and the others), the other .debs (Perplexity, LM Studio, Bitwarden, Minecraft, Heroic, Sunshine, umu, Obsidian), Ollama's release tarballs in `/usr/local`, libretro files, Zed and Zen stay at the installed version until removed and installed again. Hermes Desktop's node-pty is rebuilt locally because the Omarchy build needs glibc 2.42 |
| Default package set | the installer lays down `install/omarchy-base.packages` (`omarchy-pkg-defaults` from 4.5) once; an update never reinstalls it | step 47 installs the same set through `omarchy-pkg-ubuntu` at bootstrap: the aliases and recipes of the Install menu, skip recipes for what does not apply (pacman's tooling, sddm, ufw-docker, Apple Silicon's Vulkan driver, the Qt modules the port's own Qt carries); the preinstalls the user removed stay out; a conflict fails that one install (`apt-get --no-remove`, as pacman's `--noconfirm` refuses one) | the port lands on an existing Ubuntu, so what Ubuntu already has is kept as it is |
| Update | `omarchy-update` (pacman, snapper, keyring) | `omarchy-update-ubuntu` (fork patch 0002): the port fast-forwarded, the `ubuntu` branch rebuilt on the channel's tag with the port's patches, the pinned tools and the pieces outside the checkout brought up to it, the port's own migrations (`migrations/`) and then upstream's new ones, `lib/migrations.sh` deciding the Arch-only ones (Limine, mkinitcpio, `pacman.conf`, the N1x kernel and its boot drop-ins: marked done; the ones that step aside on their own run as they are); upstream's update inhibitor (`omarchy-update-stay-awake`) runs under umask 022 and its state left by an earlier run loses group write first | migrations and updates assume pacman; Ubuntu's umask is 002, so 4.0's inhibitor leaves group-writable state that 4.5's refuses, and an update from one to the other would keep the inhibitor held |
| Channels | `omarchy-channel-set` picks a pacman ring (stable, rc, edge) or links a checkout (dev); `omarchy-version` and `omarchy-update-available` read the package | the same four names, handed to `omarchy-channel-ubuntu` by the channel patch (stable `0013`, rc `0010`): stable and rc are tags pinned per channel in `versions.env` (`versions.rc.env` for what rc builds differently), edge is upstream's default branch, dev leaves the checkout alone; the choice lives in `~/.local/state/omarchy/channel`. `omarchy-update-available` also reports this repository behind its tracking branch, which upstream has no counterpart for (its settings package moves with the omarchy package) | no package ring; a tag is pinned once the port was checked against it, as a release only reaches upstream's ring once omarchy-pkgs built it |
| Qt / Quickshell | distro packages: Arch's Qt, Omarchy's Quickshell package (a pinned commit with a patch for Qt 6.12) | the same Qt version from aqtinstall in `~/.local/opt/Qt`, Quickshell at the same commit with the same patch (fetched from omarchy-pkgs), built with a compat header for `wl_fixes`; `omarchy-pkg-ubuntu` counts the `qt6-*` package names as provided by that tree, so migrations that add them install nothing | noble has Qt 6.4 and libwayland 1.22 |
| ImageMagick | `magick` (IM7) | `/usr/bin/magick` shim to `convert` | noble ships IM6 |
| vipsthumbnail | `--path` (libvips 8.16+) | `/usr/local/bin/vipsthumbnail` wrapper turning `--path` into `-o` | noble ships libvips 8.15; a wrapper instead of a patch on `omarchy-menu-images`, which upstream rewrites often |
| I/O scheduler | `60-omarchy-io-scheduler.rules` sets kyber (built into Omarchy's kernel) | same rule plus `modules-load.d/omarchy-kyber.conf`, once the rule is in the checkout's tag | kyber is a module on Ubuntu's kernel |
| Session env | `/usr/share/uwsm/env.d/10-omarchy` | block in `~/.config/uwsm/env` and at the top of `~/.bashrc`; Lua glue in `hyprland.lua` for the direct GDM entry | the PPA's uwsm 0.26 ignores `env.d`; the direct entry has no login shell |
| User units | started by `graphical-session.target` | same under uwsm; `autostart.lua` also starts them for the direct entry | `graphical-session.target` refuses manual start |
| Lock PAM | `system-local-login` + `pam_faillock` | `pam_unix`/`pam_sss` stack, `common-account`; fingerprint in its own stack | no faillock on Ubuntu; the 4.5 fingerprint and FIDO2 setups write `include system-auth`, which would have to become `@include common-auth` here |
| Polkit PAM | `/etc/pam.d/polkit-1` written by the fingerprint setup | same file, Ubuntu modules | Ubuntu has no `polkit-1` PAM file; the dialog needs it to show fingerprint mode |
| Polkit identities | wheel = the user | rule returning the requesting sudo user | Ubuntu offers the whole sudo group; the agent picked the first member |
| Packaged helpers with sudoers rules | `omarchy-theme-set-browser-policy` and (4.5) `omarchy-locale-generate` in `/usr/bin`, `%wheel` sudoers | copies of both in `/usr/bin`, `%sudo` (step 70, reapplied by the updater); Firefox skipped (snap) | the packaged paths are hard-coded upstream |
| Passwordless sudo | `omarchy-sudo-passwordless` (4.5) works under a root lock in `/run/lock`; the package puts it, `omarchy-security-functions` and `omarchy-shell` in `/usr/bin`; an ALPM hook revokes temporary grants before the settings package changes, and temporary grants require that hook and the boot cleanup rule; migration 1788163635 clears the old helper's grants through it | the rc series' patch takes the lock in `/run` (root, 0755) and requires only the boot cleanup rule; step 70 keeps root-owned copies of the three in `/usr/bin`, runs `__package-removing` before it replaces or removes them (stopping if revocation fails, as `AbortOnFail`) and clears that marker once the boot rule is in place, as the package's scriptlet; the old helper's grants are cleared and the migration marker written by the port's migration `1792592191`, so upstream's migration passes. Upstream's passwordless test suites pass against the patched helper, the hook assertion read as the boot rule's | `/run/lock` is world-writable (1777) on Ubuntu; no ALPM, the port's own step is what changes those files |
| Input method | fcitx5 from pacman | fcitx5 from apt; Ubuntu's IBus autostart hidden | uwsm honours XDG autostart |
| Input method theme | Omarchy's candidate-window theme (4.5) links `prev/next/radio/arrow.svg` out of fcitx5's packaged default theme | the four SVGs from fcitx5 5.1.22's source in `/usr/share/fcitx5/themes/default`, beside noble's PNGs (step 58) | noble's fcitx5-data 5.1.7 ships the PNGs only |
| Hardware firmware packages | `dell-xps13-sidecar-amps`, `apple-bcm-firmware-fetcher`, `linux-firmware-cirrus-dx13260`, `asus-proart-p14-speaker-firmware`, `linux-omarchy-n1x` and their migrations | skip recipes in `omarchy-pkg-ubuntu`; the sidecar-amps (1787666837) and N1x migrations marked done in `lib/migrations.sh`, the ProArt (1790973240) and Dell PTL (1791265613) speaker ones run as upstream's behind their hardware guards and land on the skip recipe | Ubuntu's kernel and linux-firmware carry those drivers; the N1x kernel is Arch's |
| Cam Link 4K | migration 1788862626: a v4l2loopback device through `v4l2loopback-ctl add` and a `v4l2-relayd@camlink` relay, on Omarchy's v4l2-relayd 0.2.0 | the port's migration `1792636073-camlink-4k` supplies what noble lacks, then runs upstream's migration as it is (the updater's loop marks 1788862626 done so it runs only there): Omarchy's 0.2.0 base and template units in `/etc/systemd/system` (`etc/systemd/system/`), and the Cam Link's device made when the module loads (`etc/modprobe.d/zz-omarchy-camlink-4k.conf`: two devices, "Virtual Camera" and "Cam Link 4K", both with exclusive caps), which upstream's unit finds, so it never asks for `add`; the running kernel's headers and `acl` with the packages. Pending while v4l2loopback is held; the next boot loads it with the device | noble's v4l2loopback 0.12.7 cannot add a device at runtime; its v4l2-relayd 0.1.2 has no per-camera template and its base service relays a test pattern, enabled by its postinst |
| Screen recorder capability | package `.install` sets it | `setcap` in the root step on `~/.local/bin/gsr-kms-server` | user-local install |
| Hardware video on Intel's xe driver | Arch's libva and intel-media-driver drive Xe2 (Lunar Lake, Battlemage) | where an Intel GPU runs on the xe driver, step 13 takes the media stack (libva, intel-media-driver, gmmlib, oneVPL, vainfo) from Intel's graphics PPA (`ppa:kobuk-team/intel-graphics`), pinned in `/etc/apt/preferences.d/omarchy-intel-graphics-media` so its kernel and compute runtime never come from it; a machine bootstrapped before the step takes it at its next update; `OMARCHY_INTEL_MEDIA=0` keeps noble's stack, `=1` takes Intel's on any GPU; `install/13-intel-media-root.sh --undo` (as root, with `REPO_DIR`) removes the PPA and the pin and brings noble's versions back; both it and `=0` are remembered in `.applied/13-intel-media-declined`, so updates keep noble's stack until `bootstrap.sh 13` runs again | noble's libva 2.20 does not map the xe driver to iHD and its intel-media-driver 24.1 does not initialize on Xe2, so VA-API is gone: screen recordings fall back to the CPU, and Sunshine with them. Intel's own route for these chips on 24.04 is that PPA |
| Crash capture | systemd-coredump, part of Arch's `systemd`, journals each core dump and `omarchy-crash-watch` turns it into the crash notification | `systemd-coredump` from apt (`packages/apt-runtime.txt`): it takes `core_pattern` and replaces `apport-core-dump-handler` where that is installed (both provide `core-dump-handler`); apport hooks into it, so its reports go on | Ubuntu ships systemd-coredump apart from systemd; without it no core dump reaches the journal and the watcher never fires |
| tmux | 3.7 from pacman | apt 3.4 stays (byobu depends on it); `/etc/mise/conf.d/omarchy-ubuntu.toml` puts mise's tmux first | Omarchy's tmux.conf uses `extended-keys-format` (3.5+) |
| Port tool versions | pacman | tmux, herdr and cliamp declared in `/etc/mise/conf.d/omarchy-ubuntu.toml` (system level, herdr and cliamp from `versions.env`); the steps only `mise install`, never `mise use --global` | the user's `~/.config/mise/config.toml` travels with their dotfiles; mise's system config is the lowest precedence, so their declarations win |
| mise defaults (4.5) | `/etc/mise/conf.d/omarchy-tools.toml` from the settings package declares the default tools as lazy shims; migration 1791382872 retires the wrappers `omarchy-mise-install` wrote, matched byte for byte | the same file from the checkout (step 57), the shims rebuilt after it; the port's migration `1792592500` retires the wrappers the port's mise-wrappers patch wrote (`patches/rc/0008`, stable `0011`), which upstream's match skips | the lazy shims need mise 2026.10.11+, pinned in `versions.env` |
| Companion apps | Arch packages from Omarchy's repository (omacalc, omawrite, omacut, hype, monologue, omasnap, owe, owe-lockfeed, signed) | built from source against the port's Qt by `omarchy-build-app`, into `~/.local`, and brought to their pins by the updater (`omarchy-build-app --installed`); `omarchy-pkg-ubuntu` has a recipe for each, so `omarchy-pkg-add` and the migrations that install them work; owe's theme hook is also copied to `/usr/share/owe/10-owe-sync` and omasnap's launcher to `/usr/share/applications`, where upstream's first-run and migrations look for them; tensaku is built from source while the tag's base packages list it; signed builds as C++20 and, against noble's qpdf 11, with one `const` dropped in `stamper.cpp` at build time; against noble's poppler 24.02, which has no `PDFConverter::lastSigningResult` (poppler 25.08), `patches/apps/signed-poppler-without-signing-result.patch` makes a lost signature report one generic message instead of its reason | Omarchy's binaries link Arch's Qt and glibc; signed's links Qt 6.12, qpdf 12 and poppler 26 |
| Window titlebars | `omarchy-hyprland-titlebars`, a Hyprland plugin built against Arch's Hyprland | the same plugin built by `omarchy-build-app` with g++-14 against the PPA's Hyprland headers (plus Lua 5.4's include path, which `hyprland.pc` leaves out), installed at upstream's fixed `/usr/lib/omarchy-hyprland-titlebars/titlebars.so` and rebuilt when the PPA's Hyprland version changes | a plugin must match the running Hyprland's ABI; Arch's build needs GLIBCXX 3.4.36 |
| layer-shell-qt | KDE's Qt 6 build, omasnap's dependency | built from source with ECM into the Qt tree (`~/.local/opt/Qt`); ECM needs CMake 3.29, so the build puts mise's cmake first on its own PATH (installed, never pinned in the user's mise config) | noble only packages the Qt 5 build and CMake 3.28 |
| Fonts | `ttf-jetbrains-mono-nerd`, `ttf-cascadia-mono-nerd` | Nerd Fonts release archives into `~/.local/share/fonts` | not packaged |
| Bash | skel bashrc sources Omarchy's `default/bash/rc` | only the env-bootstrap block is added; your shell config stays | personal choice; `default/bash/completions` is worth sourcing |
| Chromium | Arch's `chromium`; launcher reads `~/.config/chromium-flags.conf`; Omarchy's initial preferences | Debian's `chromium` from the xtradeb PPA, pinned so nothing else comes from it; `/etc/chromium.d/omarchy-user-flags` reads the flags file; Debian's first-run preferences diverted, Omarchy's in place; AppArmor profile granting `userns` | Ubuntu ships Chromium only as a snap, whose desktop file name, confinement and policy path break Omarchy's launchers, extensions and theme policy |
| System tweaks | `etc/` tree installed by the package; a downgrade takes the package's files away | `57-system-tweaks-root.sh` copies the same files (`%wheel` to `%sudo`, `omarchy-dns` copied to `/usr/bin`); a file the tag no longer ships goes only when it is still the port's unedited copy, and what the port wrote over (a package's conffile such as `/etc/mpv/mpv.conf`, the admin's own file) comes back from the `.bak-omarchy` copy kept beside it; `58-system-extras-root.sh` adds the pieces that need a package or an edit on Ubuntu (docker DNS, cups-browsed, zram, sleep hooks, oomd for app.slice, fcitx5's SVG glyphs) | same files, different install path |
| logind inhibit delay | `20-inhibit-delay.conf` (15 s) | same content as `zz-omarchy-inhibit-delay.conf` | Ubuntu's unattended-upgrades ships a 30 s drop-in that sorts after `20-` |
| USB autosuspend | `modprobe.d` option | same file plus a tmpfiles `w` on `/sys/module/usbcore/parameters/autosuspend` | usbcore is built into Ubuntu's kernel, so modprobe options never apply |
| zram | `zram-generator.conf.d/90-omarchy.conf` under `/usr/lib` | same content in `/etc/systemd/zram-generator.conf` | noble's zram-generator 1.1.2 reads no `conf.d`; the 4G `/swap.img` from Ubuntu's installer stays behind zram at priority -1. Upstream has no disk swap until `omarchy hibernation setup`, which needs Limine, so the port sets up no hibernation |
| cups-browsed | `cups-files.conf` with Arch's uid/gid 209, `SystemGroup cups-browsed sys root` | Ubuntu's `cups-files.conf` with `cups-browsed` added to `SystemGroup`; queue settings appended to Ubuntu's `cups-browsed.conf` | Arch ids and Ubuntu's `BrowseRemoteProtocols dnssd` |
| Docker | `daemon.json` from the package | `dns` and `bip` merged into the existing `daemon.json`, docker restarted only at reboot | local log settings kept; a restart stops running containers |
| Share picker region | `slurp -f '%o@%x,%y,%w,%h'` straight into the picker | `omarchy-share-picker-region` rebases the slurp box on its output | slurp prints global coordinates and Hyprland's screencopy takes output-local ones, so a region picked on a monitor away from the origin came out shifted; the input stack is upstream's, so this belongs upstream too |
| Microphone denoise | nothing (Omarchy tunes speakers only) | DeepFilterNet LADSPA plugin in `~/.local/lib/ladspa`, hosted like the speaker tuning by its own PipeWire client (`omarchy-audio-input-denoise.service`) and driven by `omarchy-audio-input-denoise` (`on`, `off`, `status`, `test`, `use`); the virtual source becomes the default, so the mic-mute key keeps working | the user's request; the same mechanism upstream uses for the speaker tuning |
| Not ported | mkinitcpio, limine, sddm, faillock, nsswitch, ufw-docker; pacman's tooling in the base list (`expac`, `pacman-contrib`, `yay`, `kernel-modules-hook`) | left to Ubuntu; the package names are skip recipes in `omarchy-pkg-ubuntu`, so asking for one says why | Arch boot stack, no faillock in Ubuntu's PAM, `nsswitch` carries `sss` for the corporate login, no pacman |
| Global user units | Arch enables none | `foot-server`, `fumon` and `hyprsunset` globally disabled | Ubuntu's presets enable them for every session; Omarchy starts hyprsunset from the nightlight toggle only |
| Fontconfig defaults | `50-omarchy.conf` in `/etc/fonts/conf.d` | same file in `~/.config/fontconfig/conf.d` minus its `monospace` assign; `omarchy-font-set` writes the monospace default to `fonts.conf` at install | noble's fontconfig 2.15 applies the strong assign before font-set's `prepend_first`, whose `monospace` test then never matches, so a chosen font never took effect |
| Bash: fzf | `default/bash/init` sources `/usr/share/fzf/{completion,key-bindings}.bash` | the fzf patch (stable `0012`, rc `0009`) also looks in `/usr/share/doc/fzf/examples`, where Ubuntu's package keeps `key-bindings.bash` (completion comes through bash-completion) | different install paths |

## Files this port writes into `$HOME`

Upstream installs these system-wide (`/usr/lib`, `/etc`, `/usr/share`). The port puts them in the
user's home, so a dotfiles layer must treat them as Omarchy's, not the user's:

| Path | Upstream location |
|---|---|
| `~/.config/systemd/user/omarchy-*.service`, `bt-agent.service`, `voxtype.service` | `/usr/lib/systemd/user/` |
| `~/.config/uwsm/env` (the `omarchy-ubuntu env-bootstrap` block) | `/usr/share/uwsm/env.d/10-omarchy` |
| `~/.config/fontconfig/conf.d/50-omarchy.conf` | `/etc/fonts/conf.d/50-omarchy.conf` |
| `~/.config/environment.d/10-omarchy-fcitx.conf` | `/usr/lib/environment.d/` |
| `~/.config/omarchy/hooks/post-update.d/{install-voxtype,setup-fingerprint}.hook` | package post-install |
| `~/.config/hypr/hyprland.lua`, `~/.config/hypr/autostart.lua` (Ubuntu/GDM glue) | Omarchy's templates, unchanged |
| `~/.config/autostart/*.desktop` with `Hidden=true` | not needed on Arch |
| the `env-bootstrap` block at the top of `~/.bashrc` | `/etc/skel/.bashrc` |
